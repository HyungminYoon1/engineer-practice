# 정보처리기사 실기 학습실 — 엣지케이스 감사 (2026-10-13)

이전 유지보수와 구분한 새 감사다. 기준 `b0123e2`, 신규 Node 12개 / 전체 46개 PASS. `npm run check` PASS. 공개 여부·정확한 배포 커밋은 [통합 보고서](https://github.com/HyungminYoon1/web-lab/blob/main/docs/edge-cases-20261013.md)에 별도 기록한다.

## 실패 먼저 확인한 항목

- SQL 리터럴의 전각 A·NBSP·전각 공백이 NFKC 정규화로 다른 값인데도 정답 처리됨: 신규 Node 첫 실행에서 `true !== false`. 실제 SQLite `SELECT ? = ?` 결과 0을 독립 기준으로 사용했다. 토큰형 답안에서 리터럴 정규화를 제거한 후 동일 검사 PASS.
- 다른 탭이 시험을 중단하거나 앱 기록을 삭제한 뒤 오래된 탭이 제출하면 완료 기록을 다시 생성함: 신규 Node 두 검사에서 `1 !== 0`. 현재 활성 시험 ID와 일치할 때만 완료하고, 무효 제출은 키를 다시 쓰지 않도록 수정. 동일 검사 PASS.
- 브라우저: 2100년 예정일 입력 시 저장 검증 예외, 화면을 떠난 뒤 늦게 읽힌 백업의 교체 확인창, 삭제 후 오래된 제출의 결과 20개 표시를 각각 실제 실패 확인 후 수정했다. 날짜 입력 경계·현재 파일/연결 상태·실제로 보존된 완료 결과를 확인한다. 같은 검사 모두 PASS.
- 수정된 SQL 기준과 이전 기록을 함께 지원하는 추가 호환성 검사: 저장 점수 5점/현재 기준 0점 차이를 설명하지 않음(`0 !== 1`)을 확인하고 조건부 안내를 추가했다. 이는 새 기준 적용 과정의 호환성 수정이며 별개의 기존 결함으로 과장하지 않는다. 저장된 답안/점수는 변경하지 않는다.

신규 Node 첫 묶음은 9 PASS / 3 FAIL, 수정 후 12 PASS. 기준 코드에서 이미 통과한 9개는 coverage addition이며 TDD로 고친 버그가 아니다. 과거 버전1 SQL 기록은 당시 기준 또는 현재 기준에 일치할 때만 읽고, 새 답안은 수정된 기준으로 채점한다. D11 참고.

## 재현과 증거 구분

`npm test`, `npm run check`, `npm run verify:native`, `npm run verify:dialects`가 기존 Pages CI에서 실행된다. 신규 Node 파일도 자동 발견된다. `tools/browser-edges.mjs`의 5개 검증 함수는 격리 Playwright 세션에서 실행하며, 통합 실행기는 WEB LAB `tools/verify-browser-edges.mjs`다. 브라우저는 CI에 포함되지 않는다. 새 브라우저 검사 총20개(일반16 + 날짜/늦은복원/오래된제출/이전채점 각1)가 이번 실행에서 PASS.

새 증거는 루트의 무시된 `output/playwright/edge-20261013`에 저장한다. 이전 감사 폴더를 새 결과로 덮어쓰지 않았다. RED는 수정 전 실제 도구 실행의 실패 assertion을 위에 기록했으며 코드를 되돌려 연출한 로그가 아니다.
