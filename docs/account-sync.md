# WEB LAB 계정과 정보처리기사 동기화

2026-10-22 사용자가 승인한 선택적 통합 계정 확장이다. GitHub Pages와 독립 저장소를 유지하고, 기존 인터넷보안 Neon Auth의 사용자 UUID·이메일·비밀번호·세션을 공유한다. 별도 가입이나 기존 계정 이동이 필요하지 않다. 기존 계정·인터넷보안 기록을 변경하는 데이터 마이그레이션은 없다.

## 인증과 앱별 경계

두 앱의 계정 화면에서 같은 이메일과 비밀번호로 로그인한다. 같은 브라우저에 유효한 세션이 있으면 ‘기존 WEB LAB 로그인 연결’을 선택할 수 있다. 앱별 로그인 사용 선택은 별도다. 이 브라우저의 공통 세션에서 로그아웃하면 두 앱에 반영되며, 다른 기기의 세션을 일괄 종료하는 기능은 아니다. 비밀번호는 공통이다. 갤러리에는 SDK·인증 처리·추가 저장소를 넣지 않고 계정 화면으로 이동하는 링크만 둔다.

관리형 Auth가 이메일·해시 처리된 비밀번호·세션을 관리한다. 이름 입력 없이 필수 이름에는 고정값 ‘학습자’를 사용한다. 접속 IP·브라우저 정보가 관리형 인증 기록에 포함될 수 있다. 공개 번들에는 기존 두 HTTPS endpoint만 있으며 DB 접속 정보나 관리 키는 없다. 앱 코드가 비밀번호·JWT를 Web Storage에 보관하지 않는다. 같은 출처의 BroadcastChannel에는 문자열 `changed`만 보내고 수신자는 관리형 세션을 확인한다. 이를 인증 수단으로 신뢰하지 않는다.

DB에는 `engineer_private`와 `engineer_service`를 추가한다. 인터넷보안의 `study_private`·`study_service`는 유지한다. 역할은 NOLOGIN·NOBYPASSRLS, 진행/영수증 테이블은 RLS 활성화 및 강제, 공개 테이블 접근은 폐쇄한다. 사용자 ID는 요청의 비교 조건일 뿐 권한 근거가 아니다. 서버가 검증된 JWT subject와 이메일 인증을 다시 확인한다. Auth 사용자 삭제 시 FK는 해당 사용자의 각 앱 기록을 제거한다. 앱 기록 초기화는 계정 삭제와 다르며 해당 앱에만 적용한다. 탈퇴 UI·비활성 계정 자동 삭제·유료 전환은 추가하지 않는다.

## API와 저장

모두 POST `/rpc/<name>`, `{p_request: request}` 형식이다.

| RPC | 필수 요청 | 동작 |
| --- | --- | --- |
| `engineer_pull` | appId, userId | 본인 앱 envelope 읽기 |
| `engineer_push` | appId, userId, epoch, baseRevision, operationId, state | 잠금 후 버전 비교, 검증된 스냅샷 저장 |
| `engineer_reset` | appId, userId, epoch, baseRevision, operationId | 확인한 버전만 초기화, 새 epoch 발급 |

`appId`는 `engineer-practice`로 고정한다. Envelope는 appId/userId/epoch/revision/serverNow/state를 포함한다. `status: ok/conflict/epoch`를 해석하며 HTTP 200만으로 성공을 표시하지 않는다. 같은 operationId·같은 내용은 재시도할 수 있고 다른 내용으로 재사용하면 거부한다. 영수증은 계정별 128건으로 제한하고 현재 envelope를 반환한다. 삭제된 영수증의 오래된 요청도 revision/epoch 검사로 재적용되지 않는다. 분당 120개의 성공한 RPC admission 제한을 두지만 롤백된 오류 요청까지 세는 전역 남용 방어라고 주장하지 않는다.

DB는 엄격한 필드, 타입, UUID, 문항 코드, 배열 개수, 답안 길이, 날짜, 시간 관계와 점수 범위를 검사한다. 교육용 정답·점수 판정은 기존 JS rubric과 과거 기록 호환 규칙을 그대로 사용하며 서버 인증 점수로 취급하지 않는다. 공개 순위가 없다. DB JSON의 UTF-8 직렬화 상한은 4,500,000 bytes이며, 브라우저는 기존 compact JSON 1,048,576 UTF-16 문자 한도를 더 엄격하게 적용한다.

## 로컬 기록과 전송

- 비로그인: 기존 `engineer-practice-v1` 그대로. 로그인 시 자동 가져오기·삭제하지 않는다.
- 계정: `engineer-practice-account-v1:<UUID>`. 기준 envelope, 현재 로컬 기록, 정확한 전송 중 요청, 충돌한 계정 사본을 보관한다. 계정 캐시의 직렬화 한도는 8 Mi 문자이며 실제 브라우저 용량에 따라 더 일찍 실패할 수 있다.
- 선택 상태: `engineer-practice-account-mode-v1`. 인증 정보가 아니다.

계정 변경은 먼저 기기에 readback까지 확인해 보관한 뒤 전송한다. 매 전송 전 관리형 사용자와 서버의 expected-user 조건을 모두 검사한다. 응답이 사라지면 같은 요청을 재시도한다. 전송 도중 추가한 변경은 승인된 스냅샷과 현재 계정 상태를 기준으로 다시 합친다. 다른 계정의 대기 기록은 보내지 않는다. 종료한 세션의 늦은 응답은 무시한다. 저장소 거부·용량·다른 탭 변경·readback 실패 시 계정 변경을 성공으로 표시하거나 전송하지 않는다. 입력 화면의 미저장 답안은 직접 복사할 수 있다. Web Storage에는 원자적 다중 탭 트랜잭션 보장이 없다.

서로 다른 풀이/완료 시험과 비충돌 설정은 기준·로컬·계정의 세 상태를 비교하여 합친다. 기기 시각으로 우선순위를 정하지 않는다. 충돌은 원본 백업 후 계정 값 또는 기기 값을 선택한다. 제출된 시험과 다른 작성 중 답안의 충돌, 합친 기록의 용량 초과는 자동 정리하지 않고 두 원본을 백업한 뒤 명시적으로 최신 계정 기록에 재연결하도록 안내한다. 다른 기기에서 초기화한 epoch도 자동 복원하지 않는다.

가져오기는 명시적으로 확인한 비로그인 풀이·표시·완료 시험을 합친다. 계정 설정과 진행 중 시험, guest 원본은 보존한다. 같은 ID의 다른 내용이나 합친 기록의 한도 초과는 거부한다. 일반 학습의 기존 보관 정책은 풀이 2,048건, 표시 문제 128개, 완료 시험 20회, 진행 중 시험 1회다. 새 기록의 한도 초과는 기존 store의 오래된 항목 정리를 따르되 가져오기/병합을 임의로 잘라 넣지 않는다.

모의시험은 기존 150분 절대 마감을 유지한다. 서버 감독·부정행위 방지 서비스가 아니며 시간/채점은 기존 클라이언트 규칙이다. 두 기기에서 같은 답안을 동시 수정하면 충돌 확인이 필요하다. 앱을 새로 여는 완전한 오프라인 캐시 기능은 추가하지 않는다. 이미 열린 계정 화면은 연결이 끊겨도 대기 기록을 기기에 보관할 수 있다.

## 검증과 운영

`tools/db-migrate.mjs`는 체크섬을 확인하여 새 구조만 추가하고 기존 데이터는 옮기지 않는다. DB 도구는 기존 프로젝트 호스트만 허용하고 TLS를 검증하며 오류를 정제한다. 접속 정보는 프로세스에만 전달한다. 운영 테스트는 `tools/live-account-check.mjs`로 이번 실행의 임시 example.com 계정만 만들고 ID+이메일 조건으로 정리한다. 메일함 수신 검증과 테스트용 인증 상태 설정을 구분한다. `--candidate`는 기존 허용된 HTTPS origin에 후보 dist를 테스트 브라우저에서만 제공하므로 Auth origin 설정을 넓힐 필요가 없다. 일반 CI에서는 실제 계정·운영 DB를 사용하지 않는다.

Chromium/Firefox의 관리형 세션과 WebKit의 타사 쿠키 제한을 각각 기록한다. iOS/Android 실기기 검증을 데스크톱 브라우저 엔진 검증으로 대신했다고 주장하지 않는다. [Neon 인증 흐름](https://neon.com/docs/auth/authentication-flow), [Data API 접근 제어](https://neon.com/docs/data-api/access-control)를 따른다.
